# Gravilog 备份与恢复策略

Gravilog 的数据原则是：用户最终只需要管理一个可携带的 JSON 文件。当前版本会把导出和链接文件写成 v2 单文件结构，同时继续兼容旧的 v1 JSON。

## 数据位置

Gravilog 同时使用三类存储位置：

- 浏览器本地缓存：`localStorage` 保存正文、日期、统计、日程和保存时间。
- 浏览器 IndexedDB：保存用户授权过的文件句柄，只用于恢复“链接文件”能力。
- 用户选择的 JSON 文件：导出或链接文件时写入，建议放在云盘同步目录中。

浏览器本地缓存适合短期自动保存，不应作为唯一长期备份。长期备份应以导出的 JSON 或链接 JSON 文件为准。

## 推荐备份方式

推荐使用“链接文件”作为主备份方式：

1. 在云盘同步目录中创建或选择一个 `diary.json`。
2. 在 Gravilog 中点击“链接文件”并选择该文件。
3. 等右侧存储状态显示已同步后，再关闭页面或切换设备。

建议再定期手动点击“导出”，保留按日期命名的快照，例如：

```text
diary_2026-05-17.json
```

## 恢复方式

如果浏览器本地数据还在：

1. 打开 Gravilog。
2. 如果提示恢复上次同步文件，优先选择原来的 `diary.json`。
3. 等待同步完成后进入编辑。

如果浏览器本地数据丢失：

1. 打开 Gravilog。
2. 点击“导入”。
3. 选择最近一次导出的 JSON，或云盘中的 `diary.json`。
4. 确认内容正常后，再重新执行“链接文件”。

## 冲突处理

当本地未同步内容和云盘文件都发生变化时，Gravilog 会进入冲突保护，不会自动覆盖任一版本。

冲突界面中：

- 左侧是本地未同步版本。
- 右侧是云盘版本。
- 中间是可编辑的合并版本。

确认合并后，Gravilog 会写回新的 v2 JSON 文件。

冲突发生时，Gravilog 会尽量把本地和远端快照保存到浏览器的 `diary_conflict_backup`。这是应急保护，不应替代用户自己的 JSON 文件备份。

## 格式兼容

当前可读取：

- v1：`doc/dates/stats/todos/savedAt`
- v2：`blocks/assets/calendar/stats/meta`

当前写出：

- 导出 JSON：v2
- 链接文件写入：v2
- 浏览器本地缓存：仍保持 v1 运行时格式

这样做可以让外部文件先进入结构化格式，同时降低编辑器运行时迁移风险。

## 恢复前检查

恢复前建议确认：

- JSON 文件不是空文件。
- 云盘同步已经完成。
- 如果同一文件被多个设备编辑过，优先在 Gravilog 的冲突界面中合并，不要手工覆盖。
- 恢复重要数据前，先复制一份 JSON 文件到安全位置。
